### Acceptance and verification

- Real coding-agent execution produces inspectable changes; self-reported success
  is insufficient. Design approval, trusted verification and final human acceptance
  remain distinct and refer to exact versions. Git remains optional.
- Existing factories/specifications/builders construct saved dependency resources;
  all work uses the canonical invocation/Program/execution integration.
- Required authorization, private credentials, durable review, bounds, cancellation,
  truthful observation and owned-resource cleanup work alongside the feature.
- Use application/adapter contracts, native HTTP/storage/execution and production
  clients during construction; actual browser-to-API-to-worker evidence is required
  for product acceptance. Live-provider calls are explicit, private and bounded.
- Preserve SOLID/hexagonal boundaries, cohesive classes, minimal idiomatic Python,
  precise types, meaningful models/enums and async resource ownership throughout.
